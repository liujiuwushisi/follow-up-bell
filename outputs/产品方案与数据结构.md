# 任务跟进小组件｜产品方案

## 1. 产品目标

把零散项目收进一个始终显示的 macOS 桌面任务板，并在每天 11:00、15:00、20:00 逐条追问进度。任务板默认贴在屏幕右上角、跨桌面空间显示，不能被误关；它解决的是“项目持续在眼前并记得跟进”，不是替代完整项目管理系统。

## 2. 核心体验

1. 点击“导入项目”，一次选择 JSON 或 CSV 文件；首次启动也可载入示例。
2. 首页按分组展示项目、当前进度和上次跟进时间。
3. 到提醒时间，窗口置顶并进入提醒模式，小人举着喇叭询问：`你【项目】有没有去跟进度了？`
4. 点击“有了有了”，记录本次跟进并切换下一条；全部完成后回到项目列表。
5. “现在提醒”用于随时补跟进和演示，不影响定时提醒。

## 3. 范围边界

- 原型是菜单栏常驻的 AppKit 浮窗，不是 WidgetKit 小组件。WidgetKit 不适合持续弹窗和逐条交互。
- “一键导入”指一次导入一个包含全部项目的 JSON/CSV 文件；连接 Notion、飞书、Jira 等属于后续适配器。
- 应用退出后无法执行提醒；后续可补开机启动和系统通知权限。

## 4. 数据结构

```json
{
  "version": 1,
  "groups": [
    {
      "id": "growth",
      "name": "增长项目",
      "projects": [
        {
          "id": "launch-campaign",
          "name": "新品发布",
          "progress": "等待设计稿终版",
          "owner": "小王",
          "lastFollowedAt": "2026-08-05T03:20:00Z",
          "isArchived": false
        }
      ]
    }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---:|---|
| `group.id` / `project.id` | 是 | 稳定唯一标识；重复导入时用于更新而非制造重复项 |
| `group.name` / `project.name` | 是 | 展示名称 |
| `progress` | 否 | 当前进度或下一步，缺省显示“待补充进度” |
| `owner` | 否 | 当前跟进对象 |
| `lastFollowedAt` | 否 | ISO 8601 时间；点击“有了有了”后自动更新 |
| `isArchived` | 否 | 归档项目不进入提醒队列 |

CSV 表头：

```csv
group,project,progress,owner
增长项目,新品发布,等待设计稿终版,小王
产品迭代,搜索优化,等待灰度数据,小李
```

## 5. 状态与提醒规则

- 项目数据保存在 `~/Library/Application Support/FollowUpBell/projects.json`。
- 当天每个提醒时段只触发一次；应用在时点之后才启动时，不追补此前错过的时段。
- 每轮按“分组顺序 → 项目顺序”提醒所有未归档项目。
- 点击“有了有了”只表示本轮已跟进，不代表项目完成；项目会在下一提醒时段再次出现。

## 6. 后续扩展

- 数据源适配器：Notion、飞书、Jira、Linear、CSV 自动同步。
- 每个项目独立提醒频率、暂缓、负责人和截止时间。
- 系统通知、开机启动、周报导出、跟进历史与逾期统计。
